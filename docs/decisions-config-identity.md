# Current configuration identity — 2026-11-07

- **I1: Bind reuse to current inference inputs.** `capture_model_identity(controls_root, artifact)` is a synchronous read-only helper for the parent run signature. It hashes current base-manifest bytes, pinned base revision, base `config.json`, and available/manifest-required `generation_config.json` and `tokenizer_config.json`. For adapters it independently hashes current adapter-manifest bytes, `adapter_model.safetensors`, and **all bytes of `adapter_config.json`**. Changing only alpha, rank, scaling/mode flags, inference mode, dropout, other config fields or formatting changes the identity even when adapter weights and training manifest stay unchanged.
- **I2: No duplicate full-base weight pass.** Existing provenance verification independently rehashes all eight base files. This helper does not repeat the approximately 1 GB base-weight hash. It reads only small configs/manifests, adapter weights, and current recipe source files. Parent must retain full-base provenance verification before restoring observations or evaluation caches; this helper does not replace that check.
- **I3: Record recipe without secrets.** Identity includes the recorded system-prompt hash and current `controls.py`, `evaluation.py`, and `orchestrator.py` source hashes, binding runtime prompt/generation/scoring code alongside parent cloud-model/source configuration. No environment file, token, arbitrary environment dump, model import, network, inference or cache write is used. Safe adapter parameter fields expose rank/alpha/modes for review; complete config bytes remain bound by SHA-256.
- **I4: Fail closed.** Require valid pinned model/revision, manifest digests/system prompt, model-type configuration, adapter base identity and artifact identity, current adapter weights matching their manifest, valid rank/alpha/dropout/mode/task/target/scaling-pattern types, and well-formed JSON. Reject duplicate JSON keys, nonfinite constants, missing/oversized required JSON, unsupported artifact labels and any resolved path outside the project. Resolve the pinned snapshot by its validated project-cache path without invoking a download helper. Configuration-only changes are captured rather than silently treated as equivalent to the training-manifest settings.

New/current identity is recorded with each run signature. A loaded in-memory `LocalControls` model is a separate state: if disk configuration changes, parent must reject or reload that stale loaded instance before a fresh run; a disk identity alone does not prove loaded-state equivalence.
