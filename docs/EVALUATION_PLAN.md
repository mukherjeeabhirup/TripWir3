Operational status and artifact verdict are separate reporting dimensions, not assumed API fields:

| Operational status | Artifact decision rule |
|---|---|
| **complete** | Mandatory checks and evidence validation finished. PASS means only no evidence found within those tests; FLAG means unresolved observed concern; QUARANTINE requires reproducible conditional behavior and valid provenance. |
| **degraded** | A prespecified tolerated fault occurred, but every mandatory check still finished with valid evidence. Report the fault alongside the same evidence-based verdict. A missing required result is not merely degraded. |
| **INCOMPLETE** | Required work, provenance, coverage, identity, or terminal consistency is missing/invalid. Withhold an accepted final artifact verdict. Retain independently supported concerns as provisional findings; do not translate an outage into a maliciousness accusation. |

Only independently supported QUARANTINE counts as strict detection. FLAG is triage, not proven conditional behavior. Low rank, high norm, a model-card allegation, or unavailable reference weights alone cannot justify QUARANTINE. A benign deployment hold due to uncertainty is an operational cost, separate from an artifact false alarm.

Otherwise fail **LOCAL MODEL NEEDED before the run**. Merely listing a model is insufficient. Any specialist fallback during capture must be visible and abort/disqualify the hero; do not relabel it as Nano. Offline replay must never initialize or call providers. These are future gates; none is executed here.
