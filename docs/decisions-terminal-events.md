# Terminal events, accepted recordings, and replay provenance

- Introduce `model_customs.recordings.accepted_real_recording`, a pure standard-library predicate returning an immutable acceptance result plus error categories. The catalog, replay admission, replay task, packager, and live API completion all use this same predicate. Checksums remain a separate byte-integrity check and are insufficient for source acceptance.
- Accept an original real recording only when the report's run ID matches the source folder/request ID, origin is `real_local_inference_and_live_nemotron`, mode is `live`, artifact/verdict are recognized controls/dispositions, and `agent_grounding.passed is True`. Reject replay-origin sources, malformed/non-finite JSON payloads, inconsistent optional event run IDs/origins/modes, and malformed event fields. Declared origin and local checksums are not a signed attestation of scientific validity.
- Require exactly one terminal event, at the end, with type `complete` and data equal to the report. Any source error/cancellation terminal anywhere, duplicate completion, event after completion, missing terminal, report mismatch, or malformed event invalidates the whole recording. Raw historical traces are retained unchanged rather than repaired, relabelled, or whitelisted.
- Queue a producer's proposed terminal inside `do_audit`. Publish completion only after `Investigation.run()` and its cleanup finish, the model lock is released, the persisted report equals the returned report, and the shared predicate accepts the candidate event sequence. A cleanup failure, cancellation, duplicate terminal, or post-terminal observation discards the queued completion and emits one ordered error terminal; `done` then closes SSE. The report endpoint refuses a merely written report until completion is accepted.
- Persist SSE events before exposing them in the in-memory stream; refuse subsequent emission after a terminal. This prevents a frontend from seeing a success followed by a cleanup error. Active/error state cannot enter the replay catalog just because a report file exists.
- Validate the complete source snapshot before replay admission and again when its task starts. Invalid sources emit no replay completion. Historical direct event/report endpoints reject an unaccepted completed source. The catalog resolves a source ID using the same live-folder precedence as replay, preventing a valid packaged copy from advertising an invalid shadowing live copy.
- Preserve original source event timestamps and payloads on disk. A replay copies events into a separate session and adds an explicit replay envelope. Its rewritten completion report uses the new replay session ID and retains `source_run_id` for the original capture. Replays never become eligible original recording sources.
- Packaging reads evidence bytes into one in-memory snapshot, validates that report/event pair with the shared predicate, and writes those exact bytes into a new destination. It never overwrites an existing package. Packaged reads verify both manifest checksums and the actual parsed report/event snapshot, preserving the distinction between checksums and terminal semantics. `bundle_demo.py --help` exits before reading/writing evidence or making calls.
- Replay provenance returned by POST `/api/replay/{source_id}`, carried on every replay envelope, and saved in the final replay report includes `source_run_id`, `source_recorded_at`, `source_models`, and `source_model_basis`. Recorded time comes only from the original first event timestamp. Models come from HTTP-success cloud call records without parse errors; if absent, a signature primary is labelled `configured_primary_fallback_not_observed`. Missing metadata stays missing.
- The existing live/replay renderer now visibly displays original capture ID, original recorded time, observed cloud model(s), and a separate new replay session ID. Configured-but-unobserved model fallback receives that explicit label. No new timestamp/model is manufactured, and a new replay ID is never presented as the source capture ID.
- Validation: `.venv/bin/python -m pytest tests/test_recordings.py tests/test_api.py tests/test_bundle.py -q --basetemp .cache/pytest-terminal` passed 47 tests. Cases cover complete/error/extra events, duplicate and missing completion, cancellation, report mismatch, malformed payloads, origin/mode/run-ID mismatch, grounding failure, source revalidation, queued cleanup/cancellation, blocked premature report access, source byte preservation, shared API/packager rejection, and side-effect-free packaging help. These are explicitly labelled temporary software fixtures; no real inference evidence or captures were generated.
- Frontend validation: `.venv/bin/python scripts/check_frontend.py --require-node` passed genuine Node syntax parsing plus HTML/literal-reference checks. An isolated in-memory Node DOM contract verified the original source ID/time/model, separate new session ID, honest absent metadata, configured-primary fallback label, and the existing live/replay rendering flow. No browser work, live API/model calls, network calls, new installs, or Git mutations were performed for this change.
