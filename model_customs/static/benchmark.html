01 / How these numbers are calculated

The unit is a unique adapter, with one selected audit run per row. Repeated runs and prompt counts do not increase the adapter denominator. Positive truth means a known injected target or backdoor; negative means a known clean control; unknown means truth has not been established.

TPR(positive FLAG + QUARANTINE) / decided positives

FPR(negative FLAG + QUARANTINE) / decided negatives

Decided means PASS, FLAG, or QUARANTINE. INCOMPLETE remains in the cohort and all-eligible denominators. Coverage is decided / eligible; a zero denominator is shown as unavailable, never as a zero rate. Unknown-truth adapters appear in overall coverage and the ledger, but never TPR or FPR.

Cost is the sum of reported USD amounts, including incomplete runs; its reporting count shows missing amounts. Latency is the unweighted mean of reported per-adapter audit elapsed times. Missing values remain unavailable, including when every value is missing. A reported zero remains zero.

These are descriptive snapshot fractions with no uncertainty estimate. Selection, small cohorts, missing ground truth, and unfinished runs limit interpretation. The page validates the data format; it does not verify source contents or establish independent benchmark validity.

02 / Snapshot format & future measured results

This page fetches only /static/benchmark-data.json. Schema version 1 requires a dataset ID, title, description, data kind, nullable generated timestamp, and an adapters array. Each adapter supplies its ID, name, run ID, data kind, truth label and basis, verdict, sample sizes, nullable cost and latency, sources, and note.

EXAMPLE DATA / NOT MEASURED is a separate mode. Every row must match the snapshot’s data_kind (example or measured). Mixing examples and measured rows, duplicate adapters or run IDs, unsupported labels, unsafe links, or malformed fields rejects the entire snapshot. Invalid or empty data never becomes a successful result.

For measured results, publish a separate complete snapshot after collecting actual evidence. A decided measured row needs a run ID, at least one source, and at least one executed sample. Unknown or unavailable fields must remain explicit. See docs/FRONTEND_BENCHMARK.md for the exact schema and export requirements. Backend benchmark files require an explicit conversion; they are not consumed automatically.
